# 口味地图 · Taste Map

把「口味相近的博主」推荐过的店收进来，到一个新城市打开手机就能按距离看——不用再翻小红书分辨哪条是广告，也不用对着高德一个个标点。

首版是纯静态手机网页（PWA），零依赖、零后端，数据存在浏览器 localStorage 里。

## 跑起来

在这个目录下起一个静态服务器：

```powershell
cd taste-map
python -m http.server 8080 --bind 0.0.0.0
```

手机和电脑连同一个 Wi-Fi，手机浏览器打开 `http://<电脑的局域网IP>:8080`（本机用 `http://localhost:8080`）。

**打不开几乎都是 Windows 防火墙拦了入站**，用管理员 PowerShell 放行一次：

```powershell
New-NetFirewallRule -DisplayName "TasteMap 8080" -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow
```

还不行就依次排查：手机是不是同一个 Wi-Fi（不是 4G/5G）、路由器是否开了「AP 隔离」、IP 是不是变了、URL 必须以 `http://` 开头。

> 定位与 service worker 都需要 HTTPS（iOS 尤其严格）。局域网 http 下浏览器会拒绝定位，页面自动退回「人民广场」并提示；「添加到主屏幕」仍可用，但离线缓存不生效。想真正在手机上定位，见下面「部署」。

## 三屏

- **附近**：地图 + 按分数排序的推荐卡片。顶部三个模式：
  - `吃本地`：本地度权重 .46，口味只做筛选——「来都来了，就想吃当地这口」
  - `跟我口味`：口味权重 .54——「出差了，想找口对得上的」
  - `对半`：各 .28 左右，折中
  每个模式下面有一句说明；列表上方还有一行「排第 1 是 X，因为：本地招牌 · 口味 78% · 1.2km」，用来解释为什么是这个顺序。
  再下面一条是**今儿这顿**：点一下选「甜 / 辣 / 麻 / 鲜 / 浓 / 焦香 / 酸 / 臭」，加「想尝鲜还是想吃熟的」「几个人」「饿不饿」「预算」。它只在今天生效，第二天自动失效，**不动你的长期口味画像**——人不是一台恒温机器，今天想吃甜的不代表你变成甜党。
- **清单**：把店分成「稍后去吃 / 还没吃过 / 吃过的」。吃过只点两档——**好吃 / 不好吃**（不做五颗星：少想一步，命中率还算得准），结果回写到博主命中率。
- **我的**：口味画像（16 型 + 9 条滑杆）、关注的博主、数据导入导出。

## 口味是怎么算的（v2 重写）

九个维度，每个 0–5：**辣 / 麻 / 甜 / 咸 / 酸 / 油厚 / 鲜 / 锅气 / 发酵**。

用户的值是「我想要多少」，不是「我喜欢/讨厌」，所以算分是**非对称**的：

```
over  = max(0, 这家 - 你)   罚 ×1.5   ← 你嫌辣，它爆辣，重罚
under = max(0, 你 - 这家)   罚 ×0.3   ← 你爱麻，它不麻，轻罚
sim   = 1 - min(1, (1.5*over + 0.3*under) / 5)
```

再按维度权重加权（辣 1.6、咸 1.5、油 1.3、麻/甜 1.2 …），做一次对比度拉伸 `(sim-0.5)/0.45`——不然所有店都挤在 75–85%，看起来「排序没变」。

再加硬门槛：你辣 ≤1.5 而这店辣 ≥3（川菜馆），直接 `×0.55`；你咸 ≤1.5 而它 ≥4，`×0.75`；你发酵 ≤1.5 而它 ≥3（臭豆腐、内脏），`×0.6`。

总分 `s = 口味×W1 + 本地度×W2 + 距离×W3 + 博主命中率×W4`，权重随三个模式变。

**「爱藤椒但不吃辣、嫌咸」能表达**，因为麻和辣是两个独立维度——这正是这套模型存在的理由。

## 口味测试

13 题，MBTI 式：5 题直标尺（辣/麻/甜/咸/油）、5 题情境（臭豆腐、内脏、锅气、追鲜、酸）、3 题偏好（场景、旅游怎么吃、价位）。

结果是一个 9 维向量 + 一个四轴类型码（浓清 / 甜咸 / 冲柔 / 猎稳，16 个名字，如「清咸冲稳」= 椒麻党）。**类型码是装饰，向量才是本体**——它只用来让你记住自己是什么人，排序不用它。

结果会直接写进「我的口味」，之后随时可以拖滑杆微调，改完立刻影响附近排序。

## 今儿这顿（临时状态）

长期画像是「我大体上是什么人」，今儿这顿是「我此刻想吃什么」。两者分开存：

```
S.me.taste          长期，9 维，滑杆或口味测试维护
S.mood = { dims, intent, scene, hungry, price, at }   临时，只有今天有效
```

`moodOf()` 一过零点就返回 `null`，排序自动回到长期画像——所以不用担心「昨天嘴馋污染了我的画像」。

状态怎么影响排序（`scoreOf` 里）：

| 选的 | 效果 |
| --- | --- |
| 味型（最多 3 个） | 这家在那些维度 ≥3.4 就加分，最多 +15% |
| 想尝鲜 `new` | 本地度权重 ×1.7 |
| 想吃熟的 `safe` | 口味权重 ×1.35 |
| 很饿了 | 距离权重 ×1.8 |
| 预算 | 超出预算的店排名自然下沉 |

## 多城市

一个城市一个 `S.city`，点标题里的城市名切换；「附近」只算当前城市的店，不会把 1200 公里外的本帮菜排上来。

- 店按 `place.city` 归属，博主按 `blogger.city` 归属（都缺省 = 当前城市）。
- 换城市**不影响**你的口味向量、打卡记录、「稍后去吃」清单——那些是跟着你走的，不是跟着城市走的。
- 没定位时，地图和距离以「该城市所有已收录店的中心点」为准，所以切到广州不会显示上海的地图。
- 当前城市没有店时，空态里直接给别的城市的切换按钮。
- 老数据（没有 city 字段）在 `migrate()` 里补：店沿用原城市，博主跟着店走。

## 数据怎么来

首版手工录入（点右下角 `+`），这是刻意的：先把「值不值得信」跑通，再解决「怎么进来得快」。
录一条推荐只要四件事：店名、位置（地图上点一下）、九维口味（按菜系预填，再拖两下）、谁推荐的。

点 `+` 会先问你要哪种方式：

1. **粘贴一条**（推荐）：把小红书/抖音/B站那条的**分享文案或链接**贴进去（iPhone 上可以点「从剪贴板读」，需要 https），自动认出平台、店名、菜名、地址、人均，剩下的你补坐标就行。
   > 只能读你贴进来的文字，读不了链接背后的页面——浏览器跨域拿不到小红书/抖音的 HTML，这一版也没有后端。
2. **空白手填**：一条一条自己录。
3. **先加一位博主**：新博主命中率显示「还没验证」，打过卡才算数。

真正「贴个链接就全自动」要三层，成本从低到高：

1. **粘一条链接解析**：小红书单篇笔记页面里通常带初始数据，能抓店名/城市/图片。抖音单篇能拿到页面但内容是视频，得 ASR。（前端解析已经做了，服务端抓页面还没做）
2. **手机分享入口**：小红书/抖音里点分享 → 存进这个 PWA（需 `share_target`，得 HTTPS）。
3. **平台官方 API**：B 站、YouTube 有开放接口，适合全自动；小红书/抖音没有，全站爬要账号池 + 代理 IP + 签名逆向，不值得。

## 店名 → 高德自动填地址和坐标

录一家店最烦的是「找坐标」。填过店名后点「按店名查高德」，会列出 6 个候选，点一条就把**地址、经纬度、所在区**一起填进表单。

要用这个功能，得先有一个高德 **Web服务** 类型的 Key（免费，5000 次/日）：

1. 打开 https://lbs.amap.com → 注册/登录 → 控制台 → 应用管理 → 创建新应用
2. 添加 Key，**服务平台选「Web服务」**（不是 JS API，不是微信小程序）
3. 把 32 位那串粘到「我的 → 设置 → 高德 Key」

技术上是 JSONP（`callback=` 参数）拿到数据，所以不需要后端、不受跨域限制；Key 只存在你自己手机的 localStorage 里。

## 店的来源：博主推荐 / 自己找的

一家店只有两种来源，数据上是两个字段：

- `bloggerId: 'b_da'` —— 某位博主推荐的，会算他的命中率，详情里显示「1 位推荐者」。
- `own: true` —— **自己找的**，不进博主列表、不算命中率，详情里显示「来源：我自己」，并在「我的 → 我找的店」单独列出。

收录表单里的「谁推荐的」第一项永远是「我自己」，因为自己找的店最多。这块以前是借一个假博主 `b_me` 装的，v8 拆掉了：老存档里挂 `b_me` 的店会在 `migrate()` 里自动改成 `own: true`，并把假博主从列表里摘掉。

## 不想看到的店：不感兴趣

店详情里点「不感兴趣」，它就从这个城市的列表和地图上消失，**但数据还在**。我的页 → 设置 → 「不感兴趣的店」可以恢复。
用途是「广州塔我已经很熟了」这一类，不是「这家不好吃」——不好吃用「不好吃」按钮，那个会回写到博主的命中率里。

## 另外两个设计决定

- **反广告靠嘴投票**：每个博主两个分——静态的口味相似度 + 动态的命中率 `(好评+1)/(打卡+2)`（贝叶斯先验 0.5）。接软广的博主，你去了不爽打了低分，命中率自己掉下去，不需要去识别广告。
- **路线不落库**：只存 POI，路线每次按「景点锚点 + 周边餐饮聚类 + 午晚饭时段」现算，所以「自由组合」是免费的。

## 数据模型

```js
// 我的口味
{ taste: { spicy, numb, sweet, salty, sour, rich, fresh, smoke, funky }, // 0-5
  price, scenes: [], categories: [], quizAt }
// 一位博主
{ id, name, platform, color, price, note, hits: { total, good } }
// 一家店 / 一个景点
{ id, name, kind: 'eat' | 'spot', lat, lng, city, cuisine, local, taste: {...},
  categories: [], price, scenes: [], dish, quote, bloggerId, own, stay }
// 一次打卡
{ id, placeId, verdict: 'good' | 'bad', rating, at, note }
```

数据在 `localStorage['tasteMap.v2']`（旧版 `v1` 会自动迁移）。「我的」里可以导出 JSON 备份。

**数据是会真丢的**：数据只在这台手机的浏览器里，iOS 的 Safari 会清掉「一阵子没打开过的网站」的本地存储，清完打卡记录就没了。所以导出那一刻会记 `lastBackup`，超过 7 天没导出，「附近」页顶上会提醒再导一份。导出的文件请存进「文件」App，别只留在下载列表。

## 部署（想真正在手机上定位）

任选其一，都免费：

- **GitHub Pages**：把 `taste-map/` 推仓库，Settings → Pages 选分支，得到 `https://<user>.github.io/<repo>/`。
- **Cloudflare Pages / Vercel**：拖这个目录上去。
- **本机临时 https**：`npx localtunnel --port 8080` 或 `cloudflared tunnel --url http://localhost:8080`。

拿到 https 地址后加到主屏（iOS Safari 共享 → 添加到主屏幕；Android Chrome 安装应用），就当一个 App 用了。
